# Step 3 — Per-domain area, power and power-gating break-even time

Branch `mix_gating_cg_pg`. **No RTL changes.** Step 3 installs the ASAP7 libraries, synthesizes the
evaluation core with the repo's Yosys + OpenSTA flow, and measures area, dynamic power and leakage
for each power-gating (PG) domain, then derives break-even times (BET). Full tables:
`step3_results.md`.

## 1. Goals (task order, step 3)

- Install ASAP7; verify the clock-gating (ICG) cell and pin names (concern 7).
- Per-unit / per-PG-domain dynamic and leakage power; LVT main corner, RVT sensitivity (concern 7).
- BET for a sweep of PG transition energies (concern 1).

## 3. Method

### Evaluation core
`VX_core_top` (the `hw/unittest/core` wrapper) synthesized with the stock flow
(`make -C build/hw/syn/yosys timing`), 800 MHz target (ASAP7 default), SRAMs black-boxed. Config as
in steps 1–2: 4 warps × 4 threads, F, TCU with WGMMA (fp16 + tf32), TFU. ASIC synthesis selects the
STD FPU and TFR TCU automatically, the same implementations simulated in steps 1–2. Sparse/MX are
off, so the TCU metadata RAM (concern 6a's always-on part) is not instantiated.

### Per-domain numbers by ablation
The flow cannot split power by unit from one netlist:
- the slang frontend inlines the hierarchy (`YOSYS_FLATTEN=0` has no effect) and mapped cells
  get anonymous names;
- `read_slang --best-effort-hierarchy` keeps only small leaf modules; units with SystemVerilog
  interface ports (all execution units) are still inlined;
- this OpenSTA build has no `report_power -hier`.

The PG domains are separate extensions, so each is measured as the difference between two core
syntheses:

| Domain | Measured as | Notes |
|---|---|---|
| TCU (incl. core-level `tcu_shared` tile buffers) | full − no-TCU | |
| TFU | full − no-TFU | |
| FPU (incl. FP CSRs) | no-TFU − no-F | `VX_define.vh` requires F for TFU, so the no-F core also has no TFU |

`cs752_tools/ablation_synth.sh` runs the four variants × {LVT, RVT} (~5 min each, three in
parallel) and reports power for every netlist at TT/SS/FF with `cs752_tools/corner_power.tcl`
(TT-mapped netlist; ASAP7 cell names are identical across corners). `cs752_tools/domain_power.py`
computes the domain tables and BETs.

Power is **vectorless** (OpenSTA default switching activity). Leakage does not depend on activity;
dynamic power here is only a scale for the BET model and is replaced by gate-level SAIF in step 8.

### Pitfall found: STA unit ordering
`set_cmd_units` must come **after** `read_liberty`: reading the Liberty file resets the time unit to
ps, and an SDC read afterwards takes the 1.25 ns period as 1.25 ps, inflating dynamic power about
1000×. The repo's `run_sta.tcl` already uses the correct order; `corner_power.tcl` does too.

### BET model
BET (cycles) = E_trans / (P_leak × T_clk), with T_clk = 1.25 ns. E_trans is not measurable with these
tools, so it is swept two ways:
- **relative:** E_trans = k × the domain's own dynamic energy per cycle → BET = k × P_dyn / P_leak,
  k ∈ {1, 3, 10, 30};
- **absolute:** E_trans ∈ {1, 10, 100} pJ.

### 4.3 BET against the step-2 idle windows (LVT, k = 1)
| Domain | Longest idle windows (step 2) | BET TT | BET SS (100 °C) |
|---|---|---|---|
| TCU | WGMMA kernels: ~97% of time in windows ≥ 1024, up to ~32,700 cycles; `sgemm_tcu`: ≤ 887 | 1,947 | 133 |

At TT only the TCU's WGMMA windows and the FPU's longest `tfu` windows clear the BET; at the hot
SS corner most long windows do.

## 5. Findings

1. **ASAP7 leakage is tiny at nominal conditions.** At LVT/TT, leakage is 0.041% of vectorless core
   power; even at SS/100 °C it is 0.56%. Perfect PG of all three domains would save at most 83 µW
   (0.013% of the core) at TT and 0.81 mW (0.17%) at SS/100 °C. This bounds the absolute benefit of
   any PG policy with these libraries, and is raised as concern 9 for a decision before step 4.
2. **BETs are long:** with E_trans equal to one cycle of the domain's own dynamic energy, TT BETs are
   ~2,000 (TCU), ~4,200 (TFU) and ~8,000 (FPU) cycles; at 100 °C they drop ~15× (133 / 310 / 605).
3. **The TCU is the only domain whose idle windows clearly exceed the TT BET** (WGMMA kernels);
   TFU windows (≤ 1,014 cycles) never do at TT.
4. **The gateable domains are a third of the core's area** (TCU 15.4%, FPU 15.2%, TFU 3.7%), so
   unit-level CG of these units addresses a large share of dynamic power.
5. **LVT timing artifact:** LVT misses 800 MHz by 3.7 ns because of an unbuffered high-fanout net
   (a minimum-size flop driving it shows 3.6 ns); RVT meets timing. The flow has no buffer repair
   before place-and-route. Leakage is barely affected; LVT dynamic numbers include some high-slew
   nets.

## 6. Limitations
- Dynamic power is vectorless; per-domain dynamic numbers (and the relative BET model) are scales
  only until gate-level SAIF (step 8).
- No clock tree (pre-CTS), so clock-network power, which unit-level CG mainly saves, is absent
  (the "Clock" group reads 0); step 9 (OpenROAD) addresses this.
- Ablation attributes shared logic that an extension adds outside its unit (decode, CSRs) to that
  domain; the FPU number includes the FP CSRs.
- E_trans is an assumption, swept rather than measured.
